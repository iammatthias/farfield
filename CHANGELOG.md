The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added
- `GET farfield.systems/api/profile` — the site's freshest public material as ready-to-splice GitHub-flavored markdown, built for the self-updating profile README: a keyless Actions cron curls one endpoint and splices three sections between markers, and every key stays on the fleet where keys live. The sections are the latest feed post (body quoted when there is one — an image-only post is just the image, never invented placeholder text — `blob://` embeds resolved to their public blobs URL, permalink), the three newest entries across posts/art/recipes/open-source (an allowlist, not "everything but feed" — a future collection is invisible until somebody decides it belongs on a README), and today's generative art plate linked and captioned. A section whose upstream is down is absent rather than empty so the splicer keeps its previous content, a ten-minute cache keeps a burst from fanning out to the siblings, upstream failure serves the last good document rather than a blank, and the whole thing rides the same per-IP rate limit and ETag conventions as the other public reads.

### Added
- pulse tells you when a target has drifted out of the fleet. Seeding is additive on purpose — a target the operator deletes stays deleted — which means it can never remove one either, so when a service leaves the fleet its uptime target keeps probing a hostname whose DNS is gone, and the only symptom is a permanent red row everyone learns to ignore (bard and dead-presidents did exactly that). The targets console now flags any target aimed at a `farfield.systems` hostname the registry no longer serves — flagged, never auto-deleted, because the operator's deletions are decisions and so are their targets. The test is the URL's host rather than the target's name, so the deliberately hand-made rows (`backup (internal)`, anything watching another project) stay clean, and a lookalike domain that merely contains the apex does not match. The badge uses a new `.badge.alarm` variant in the shared theme, the alarm ink on its own tint, same pairing as the incident rows.

### Added
- **You can text the box and it answers.** A leading `/` names a command; anything else is conversation for an agent, and that is the whole routing rule — capture-by-default and bare-URL-to-bookmark are retired, so a stray thought is no longer silently published and a shared link is no longer silently filed. The agent turn runs in the background: Photon's webhook is acknowledged immediately (holding it open for a model turn invites a delivery timeout, and a retried "do the thing" is the thing done twice), one "on it" follows only if the turn runs past a few seconds, and the answer arrives when it is ready. Two messages per request, maximum, and nothing streams — `omp -p` puts the reply on stdout and progress on stderr, so there is no intermediate output to leak. Conversations keep their own history: each thread gets a session directory, which is why a follow-up question knows what "it" was. Texted photos are staged to disk and handed over as attachments. Long work is expected rather than tolerated — `/jobs`, `/job <id>` and `/cancel <id>` are how work that is happening somewhere the thread cannot see stays visible, a turn that outlives the process is marked failed on restart rather than leaving someone waiting for a message that can never arrive, and concurrent turns queue instead of being refused. Which agent runs is a farfield-os concern (`ff-agent`, omp by default), so switching harnesses is one word in one file. The persona lives in exactly one place — an `AGENTS.md` embedded in the binary and written into the agent's workspace at boot, so the voice cannot drift from the code that speaks it — and it says the things that matter on a phone: one or two sentences, no preamble, no markdown, no narrating what you are about to do. If the agent is unreachable, slash commands still work; that half never depends on a model being funded or awake.

### Removed
- `bard` and `dead-presidents` leave the fleet. Both were always projects that happened to be hosted here rather than parts of the content backend, and they now live in the pure-internet monorepo at `bard.pure---internet.com` and `dead-presidents.pure---internet.com`, served by a second cloudflared connector sharing the same homelab ingress. Their `farfield.systems` hostnames are retired. The removal is total rather than cosmetic — `lib/fleet`, `docker-compose.yml`, `scripts/devfleet.sh`, the `Makefile`, `go.work`, `.env.example`, the CI image matrix, both `apps/` trees, their docs pages and apex cards, and the API and README service tables all drop them together, because the registry's drift tests fail CI the moment those disagree. Ports 8795 and 8796 are left unassigned so they still read as theirs against a running box. The apex ingress diagram is relaid on its 26px pitch rather than left with a gap in the bus.

### Changed
- The workspace builds on Go 1.27. The `go.work` and all twenty-seven module directives, the build image, and CI move together from 1.25, and no source needed changing — thirty single-line edits. The gain arrives on rebuild rather than through code: `encoding/json` is now implemented on top of the new `encoding/json/v2`, so unmarshal gets significantly faster at the thirty non-test decode sites (concentrated in content and feed, the fleet's busiest read paths) while marshal holds parity; the compiler emits size-specialized allocation routines that cut sub-80-byte allocations by up to 30%; `compress/flate` is faster, which reaches library's epubs, sideload's ipa parsing, and backup's archives; and HTTP/1 response bodies now drain themselves on close, so outbound connections are reused more often — pulse's checker had been doing that by hand. `go test` also runs the `stdversion` vet check by default now, which fails a build that reaches for a stdlib symbol newer than the file's own Go version.
- The docs diagrams speak one language now. The brand guide's §21 observation idiom is codified in the docs stylesheet — mono labels, filled dots for things, a hollow dot for a thing set apart, the accent signal-in-field node for the subject, dashed trajectories, dotted for private — with one routing rule: plumbing never crosses a label, so charts are drawn as trunks and buses instead of fans through text. The index ingress chart is redrawn that way, and five apps gain observations built from their real mechanism: blobs (same bytes, same CID, stored once), backup (the retention ladder as a timeline that thins with age), pulse (uptime measured from outside, traffic from inside), sideload (a build installs from a link; the disk is a cache over R2), content (embeds resolve by address at render, never by copy). The figures move at the brand's two speeds: dashes drift slowly along trajectories and the subject's ring breathes (atmospheric), while the full-view dialog opens in 160ms (interface); dotted private lines hold still — motion means traffic, and the tailnet doesn't advertise — and `prefers-reduced-motion` stills the plate entirely. A figure always fits its column; a "full view" toggle above each plate opens it at reading scale in a pannable dialog (scroll, touch, or mouse drag — a drag can never fall through to the backdrop dismiss). The docs stylesheet's immutable `?v=` finally bumps too; it had been pinned since June, so no stylesheet fix was reaching a warm cache.

### Added
- Sideload's builds survive the disk: with `SIDELOAD_BACKEND=r2` the shared bucket is the durable truth and the blob directory becomes a write-through cache — an upload is not acknowledged until R2 holds it, a cache miss refetches once, and ranged OTA serving still reads local files. `sideload sync-store` uploads anything local the bucket lacks (the one-time migration, and the repair after any R2 outage).
- `blobs reconcile [--confirm]` closes the byte-store's open loop: it lists the store and subtracts every CID something still references — blobs media and thumbnails, library books/covers/thumbs, backup snapshots, sideload builds and screenshots — and reports (or deletes) the orphans. It refuses to run if any sibling database is unreadable, and never touches objects younger than an hour, since every writer stores bytes before committing its row.
- `backup verify [app]` is the restore drill minus the restore: it pulls the newest snapshot of each app from R2, runs `PRAGMA integrity_check` across every page, and requires a non-empty schema. A backup that has never been read back is a hope, not a backup.
- An external uptime canary: a scheduled GitHub Actions workflow probes the fleet's public /status surfaces every half hour from outside the homelab, so a dead tunnel or box finally has a watcher that doesn't live behind it.

### Changed
- The fleet has a single source of truth: `lib/fleet` holds every service's name, internal port, and public host. The apex status page probes it, pulse seeds uptime targets from it (additively — a target the operator deletes stays deleted), and drift tests fail CI when docker-compose.yml or devfleet.sh disagree with it. An apex test requires a docs page per service, which is how pulse and scrap finally got theirs.
- Delivery is edge-friendly: `/blobs/{cid}/meta` is `immutable` like the bytes (meta is derived from content, once), `/api/entries?bodies=0` serves the slim list for index surfaces, and every 404 and JSON error across the fleet carries `Cache-Control: no-store` — a zone cache rule was observed pinning "not found" at the edge for hours over blobs that had since arrived.
- Pulse tells humans from robots: `lib/pulse` classifies declared clients (crawlers, HTTP libraries, scanners) at record time, and the collector folds them into a single "(bot)" row per day that never counts as a visitor or referrer. Non-bot 404s collapse into "(not found)" the same way, so a scanner sweeping ten thousand guessed paths no longer mints ten thousand `hits_daily` rows. Charts draw in theme ink (`currentColor` + the alarm plate) instead of hex from a retired palette, and feed post bodies take the editorial serif.
- The fleet's shared theme is re-cut to the brand guide's product language (v4 "far field", replacing v3 "engraved plate"): Paper ground with Deep Space text by day, Deep Space with Paper text and a Horizon-orange accent by night. Inter carries the interface, Newsreader appears only where writing is editorial — rendered documents (`.prose`, the rich editor, the entry title) — and IBM Plex Mono marks observation: data values and the tiny uppercase column heads, badges, and stacked-table captions. Small caps and double rules retire; the masthead keeps the page's one 2px horizon rule and everything below it is a 1px hairline. Buttons are compact with the accent reserved for the primary action; inputs are transparent with a visible accent focus outline. All three faces are vendored into the stylesheet as latin-subset data URIs, so the fleet stays self-hosted with no font CDN and no per-app wiring. Every console changes at once because every app already consumes `lib/theme`; templates needed no edits. `/status` on apex is content-negotiated now too: browsers get a branded fleet observation page (apex probes its siblings over the compose network), while healthchecks, pulse, and curl keep the JSON contract byte-for-byte.

### Added

The apex landing page is its first implementation: a halftone hilltop plate carries the emotion, the copy sits in the open sky with one Horizon-orange action, and on tall screens the artwork holds the bottom at its own scale under a flat field that extends its sky — the planet stays small, because the point is distance.

### Fixed
- The backup pipeline no longer grows without bound. Three compounding causes had put 51 GB of snapshots in R2 on top of ~0.6 GB of actual data. First, `lib/pulse` request telemetry moves out of each app's database into a sidecar (`data/pulse/<app>.sqlite`, path derived from the app's own handle via `PRAGMA database_list`, legacy in-app tables dropped on startup) — traffic alone no longer dirties an app's database, so the backup app's content-addressed dedup finally fires and an unchanged app uploads nothing. The pulse collector reads the sidecar directory and gained a cursor-rewind guard so a rebuilt request log is collected rather than hidden behind a stale high cursor. Second, snapshots now age out on a grandfather-father-son ladder — everything for 48 hours, daily for 30 days, weekly for 90, an app's newest always — applied on every scheduler tick and by hand via `backup prune [--confirm]`; bytes leave blobs/R2 only when no registry row still references the CID. Third, pulse's `checks` table (a million rows and counting — the single largest snapshot, four uploads a day) is pruned to 45 days, comfortably past the console's longest 30-day uptime window; incidents are kept forever.

### Security
- Login brute-force protection is now built into `Auth.HandleLogin`, so every app has it: five failed passwords per client IP per minute. Only `keys` had wired the old `web.FailLimit` middleware, leaving the other ten apps' front doors unthrottled — which mattered doubly under fleet SSO, where a password cracked on any one app mints a session every app accepts. The middleware is gone; the handler owns the concern and no app can forget it.
- `web.ClientIP` believes `CF-Connecting-IP`/`X-Forwarded-For` only from a trusted peer (loopback and private space by default, `FARFIELD_TRUSTED_PROXIES` to narrow). They are client-supplied strings: anything able to open a socket to an app directly could previously rotate the header per request and defeat every limiter keyed on it — scrap's paste-token gate, sideload's magic links, the keys login.
- Published container ports bind to `127.0.0.1` instead of every interface, so the apps are reachable only through the tunnel and the local reverse proxy rather than from the whole LAN.
- Session-gated writes are checked for cross-origin abuse. `RequireSession` refuses a state-changing request (POST/PUT/PATCH/DELETE) whose Origin — or, failing that, Referer — names neither this host nor a sibling under `SESSION_COOKIE_DOMAIN`. `SameSite=Lax` already blocks a cross-site form POST in a current browser; this is the layer that holds if that attribute is ever relaxed. One change covers all 117 session-gated routes across eleven apps. Requests declaring no origin at all are still allowed, so the iOS Shortcuts and the Obsidian plugin (which use API-key routes anyway) are untouched.
- Fleet sessions gained a revocation lever. `SESSION_EPOCH` is mixed into the session MAC, length-prefixed so no two (epoch, payload) pairs can collide; changing it and redeploying invalidates every outstanding token at once. Stateless sessions previously had no answer to "log everything out now" short of rotating `SESSION_SECRET`.
- Containers run as uid 65532 (`distroless:nonroot`) with every capability dropped and `no-new-privileges`. They previously ran as root against a bind-mounted `./data`, so a compromise owned host files. **Existing deployments need a one-time `sudo chown -R 65532:65532 ./data` before the first `up`** — noted in docker-compose.yml, where the setting lives.
- `lib/pulse` no longer carries its own copy of the client-address logic. It was `web.ClientIP` minus the trusted-peer check, so the spoofing fix silently did not reach the analytics visitor key; there is one copy of that rule now.
- The bookmarks metadata fetcher refuses the private network: loopback, RFC1918, link-local, CGNAT, and multicast are blocked at dial time, on the resolved address, for every redirect hop, with a redirect cap and a scheme check. A bookmark URL is attacker-influenced data pointed at an outbound fetcher inside the homelab; it previously doubled as a probe for sibling services, the router, and metadata endpoints.

### Added
- Recipes have a structure of their own. A recipe entry now carries a fenced ` ```recipe ` block of YAML in its body, and `lib/recipe` renders it two ways from that one source: the tabular format from Cooking for Engineers — ingredients down the left, operations bracketing them rightward, each spanning the rows it absorbs — and, beneath it, the method in full prose. Neither view can drift from the other because there is only one set of data. The grid's left column carries the amount, the item and its note, so it *is* the ingredient list; nothing repeats it in a second table. It is `position: sticky`, so on the few grids too wide for a phone the operations scroll while the row keeps its label — and because the table sizes to its content and the labels rotate, most grids need no scrolling at all at 380px and the page never scrolls sideways. The layout is pinned by test against CFE's own published table, filler cells and rotated labels included; a shape no table can express (a step feeding two branches that rejoin) is refused rather than drawn wrong, and a recipe that finishes two ways draws one grid per ending. All 37 entries in the recipes collection were converted to the block and are live.

- Tests for `lib/auth` (0% → 96.8%): password and API-key comparison, session cookie attributes, and signed fleet sessions — expiry authenticated by the MAC, empty secret verifying nothing, tokens unique per mint. It decides whether a password is correct and whether a session is valid, and had no tests of its own.
- Tests for `lib/backup` (0% → 53.7%) covering the streaming restore: sidecar clearing, large round trips, an interrupted download leaving the previous database intact, and the transfer helpers over httptest.
- Tests for the restore CLI (`apps/backup` 4.9% → 29.3%) — the least-tested destructive operation in the tree: dry runs leave the target untouched, a confirmed restore swaps contents and clears WAL sidecars, an unavailable snapshot leaves the previous database intact, and no staging file survives any path.
- Tests for the blobs ingest path (24% → 35.5%): the streaming and in-memory branches agreeing on content address and MIME, dedup, oversize and empty rejection, and the crash-recovery spool sweep.
- Vault sync conflicts resolve by last edit (file mtime / frontmatter `updated` vs the server's `updatedAt`); ties keep the `.remote.md` sibling fallback. The CLI's `--prefer` defaults to `newer` with manual/local/remote as overrides.
- Farfield Sync Obsidian plugin (`obsidian-plugin/farfield-sync`): the vault syncs from inside Obsidian — ribbon/command/auto-interval, settings-held credentials, same three-way merge and state file as the CLI with byte-compatible hashing (mobile-capable, no build step).
- `content sync-vault`: bidirectional Obsidian vault sync — three-way merge with a state file, push/pull/conflict handling, verified ipfs→blob ref migration, and quiet state seeding for already-identical entries. The create API honors a provided `createdAt` so vault-authored dates survive.
- Blob hygiene: blobs' `/hygiene` scans every entry, series, and post for blob:// references and reports referenced blobs (with their references), orphans (deletable in place), and dangling refs; generated thumbnails are excluded as derived, and delete affordances hide if any source scan fails.
- Login pages carry each app's tile mark; the editor gains a keyboard cheat sheet (⌘/ or the ? toolbar button).

- Fleet search: content's `/search` (linked from the fleet menu) ranks entries, series, feed posts, and public bookmarks with on-device semantic embeddings — the corpus aggregates server-side over the read APIs, ranking never leaves the browser.
- Fleet single sign-on: set a shared `SESSION_SECRET` (and `SESSION_COOKIE_DOMAIN` for subdomain deployments) and one login works across every admin app via signed, stateless session cookies; logout anywhere ends the fleet session. Apps without the secret keep their own database sessions.
- `lib/markdown`: one shared markdown pipeline (goldmark + farfield embeds) for every admin UI — blob:// media, `[file](blob://cid)` links, series:// galleries, image alt text, and an editable-HTML renderer whose unsupported blocks round-trip verbatim.
- Rich document editor in the shared theme: contenteditable surface with formatting toolbar, markdown typing shortcuts, ⌘B/⌘I/⌘K, paste/drop upload, alt-text editing, autosave, async ⌘S saves, and a Markdown source toggle. Content and feed composers are document-first with a sticky metadata rail.

### Fixed
- `[text](blob://cid)` links used to render mangled markup; they now resolve to proper file links everywhere.
- iOS form-zoom and mobile overflow issues on the edit pages; the editor toolbar docks to the bottom edge on phones.

### Changed
- Shared page shell in `lib/web/templates/layout.html`: the `<head>` (charset, viewport, theme-color pair, favicon, stylesheet), masthead, login body, and pager live in one place instead of being copy-pasted into twelve `base.html` files and eleven near-identical `login.html` files. Apps supply a name, mark, and nav list from Go and define only `title`, `styles`, `head`, and `content`; an app can still override any shared block by defining it. Favicons are generated from the app's mark rather than hand-written data URIs. Login templates went from 163 lines to 22.
- Recurring patterns moved into `theme.css` — pager, thumbnail, swatch, table action rows, the `:target` modal shell, and the responsive table-to-cards transform (now `.stack`) — so a fix reaches every app at once.
- `web.ProxyGet` and `web.ProxyUpload` replace the copies of the editor's blobs/series proxy plumbing that content and feed each carried; both now use the streaming multipart implementation.

- Uploads stream instead of buffering. `ParseMultipartForm` was being handed the *upload cap* as its maxMemory argument in blobs, library, and feed — asking Go to hold a whole 100 MiB file on the heap — and the paths then read it again, peaking at roughly twice the file size per request. Multipart now spills to disk at 1 MiB, blobs spools to `BLOBS_SPOOL_DIR` and hands large media to the backend as a file, library parses EPUBs through random access over the upload file, and library's tus finalize reads the staging file in place rather than `os.ReadFile`-ing the assembled book. A 40 MiB blob upload and a 60 MiB EPUB ingest now hold ~21 MiB RSS.
- Backup restore streams to match backup: `backup.Pull` writes to an `io.Writer` and `backup.WriteDB` reads from an `io.Reader` (into a temp file, fsynced, renamed into place), so restoring a large database no longer loads it whole into memory and an interrupted restore leaves the previous file intact.
- `lib/markdown` resolves a body's distinct blob CIDs concurrently before substitution, so a gallery costs one round-trip's latency instead of one per image.
- The blob metadata memo in `lib/markdown` and the negative-fetch cache in `daily` are bounded. Both were keyed by an ever-growing key space (content addresses, calendar dates) and never dropped an entry, so each grew for the life of the process.
- `lib/pulse`'s `statusWriter` implements `ReadFrom` and `Unwrap`. It is the innermost wrapper — closest to the handler — so `http.ServeContent`'s copy lands there first; without `ReadFrom`, every byte of an EPUB or video download was dragged through userspace instead of via sendfile.
- `lib/keys.Check` stamps `last_used_at` at most once per five minutes per key. It ran on every authenticated request across the fleet, against one SQLite file shared by every container — an audit hint that had turned the read path into a fleet-wide write path.
- `blobs` and `library` compress their HTML, JSON, and OPDS feeds via the new `web.GzipExcept`, while raw object bytes still reach `ServeContent` untouched (Range requests verified intact). `gzipWriter` now implements `Flush`, `ReadFrom`, and `Unwrap`, so streaming responses, sendfile, and `http.ResponseController` work through the wrapper; a failed `Close` is logged rather than silently truncating a 200.
- Fleet search bounds its corpus (2000 documents per kind) and fetches the two sibling services concurrently rather than serially.
- `store.ShortID` uses rejection sampling. The previous byte modulo made the first four characters of the alphabet ~14% more likely than the rest.
- Upload spool and staging files stranded by a crash are swept at startup in blobs, library, and sideload.
